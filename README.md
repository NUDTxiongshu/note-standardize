# note-standardize

[![skills.sh](https://skills.sh/b/NUDTxiongshu/note-standardize)](https://skills.sh/NUDTxiongshu/note-standardize)

把学习材料做成**树形层级编号大纲**（思维导图式笔记）的 agent skill。
通用，不限学科。已在英语文法教材与 Transformer 长文博客上验证。

## 它做什么

给一份学习材料，产出一棵能当提纲用的树。

```
名词短语
├── 1 构成
│   ├── 1.1 名词
│   │   ├── 1.1.1 可数名词：两类
│   │   └── 1.1.2 不可数名词：四类
│   │       ├── 1.1.2.1 物质名词：用零冠词，要计算就数单位
│   │       └── 1.1.2.4 专有名词
│   ├── 1.2 限定词
│   │   └── 1.2.3 中位限定词
│   │       └── 1.2.3.1 冠词：分不定、零、定三种
│   └── 1.3 形容词
├── 2 省略
└── 3 一致性
```

## 核心方法

**两遍，两道人审。**

```
第一遍：通读 → 画骨架 ──→ 【审查者】审骨架 ──→ 结案
                          ↓
第二遍：照骨架填内容  ──→ 【同一个审查者】审产出 ──→ 结案
```

写的人和查的人必须是两个。每轮审查要两边达成一致（结案），才算通过。

**几个关键约束：**

- **骨架先审，再写内容** —— 骨架错了，后面全错；这是最省时间的一道关
- **列举项不许提级** —— 冠词展开 140 行也不许提为一级分支，它原文里属于中位限定词
- **节点写结论，不写论证** —— 「零冠词：复数、抽象、物质名词放不下 a/an 时采用」，不写来历、不写例句
- **名字够清楚的节点只写名字** —— 每多写一句就问一句：这句是不是把名字重说了一遍
- **总起句是父节点** —— 「接下来整理出最常出错的地方」+ 后面五节，要建「常见错误」这个节点

## 安装

```bash
npx skills add NUDTxiongshu/note-standardize
```

或手动把 `SKILL.md` 放到你的 skills 目录。

## 用法

这个 skill 需要两个执行者：一个写，一个审。单 agent 环境下可以让同一个 agent
先产出、再对照原文自查，但效果明显不如换人。

```
执行者 A：通读 → 骨架 → 交审查
审查者 B：对照原文挑骨架的问题 → A 逐条核对、改或驳 → 结案
         ↓
执行者 A：照骨架填内容 → 交审查
审查者 B：对照原文查「找不到 / 位置不一致 / 分散 / 挂错支」→ 结案
```

**审查的第四种失败「挂错支」最难发现**：节点有编号、有位置、名字也像，
但挂在了一个跟它无关的父节点下。只有对照原文才看得出来。

## 验证过的效果

在三个章节、两种文体上跑过（英语文法教材 3 章 + Transformer 博客长文 1 篇）：

| 材料 | 节点数 | 一级分支 | 结果 |
|---|---|---|---|
| 第二章 名词短语（22860 字） | 30–72 | 3 | 冠词、专有名词均在原文位置 |
| 第一章 基本句型（8331 字） | 33–46 | 3 | 五种句型收在一个父节点下 |
| 第三章 代词（3333 字） | 8–10 | 2 | 五类错误收在「常见错误」下 |
| 博客：注意力机制（19750 字） | 98 | 3 | 作者铺垫全删，QKV 讲清 |

**已知局限：**

- **体量不稳定**：同一材料跑多次，节点数可能差一倍（30 vs 72）。结构和内容对，粗细不固定
- **审查依赖对照原文**：脚本能查编号、断号、重复、体量，但查不出「挂错支」和「内容漏了一条」
- **博客类材料的压缩率不同**：教材能压到 4–7%，博客知识点密度高，约 10%

## 目录

```
SKILL.md           skill 本体
evals/             测试用例
scripts/           产出检查脚本（check_outline.py）
```

## 检查脚本

写完可以用 `scripts/check_outline.py` 机械核对：节点数、文字总量、最长节点、
无编号行、编号连续、重复概念、一级分支数。它查的是形状，语义还得人看。
